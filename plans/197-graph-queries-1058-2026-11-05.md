# Plan 197 — Graph queries and saved views (#1058)

Status: implemented on `feat/1058-graph-queries` (2026-11-05).

## Problem

The graph could draw, focus a neighborhood, and diff revisions, but could not
answer structural questions: how two entities are connected, what the graph
looks like under a filter, or how to come back to a curated canvas setup. The
MCP bridge (#1056) also had to defer its `find_path` tool.

## Decisions

1. **One pure query module.** `src/lib/studio/graph-query.ts` owns filtering and
   shortest-path search. It takes plain arrays and returns plain data, so the
   canvas, the AI tool registry, and the MCP package can share the semantics.
2. **BFS, undirected, deterministic.** Links are traversed in both directions
   (matching how the canvas draws them), each node is enqueued once (cycles
   terminate), and neighbors are sorted by display name so the same corpus
   always yields the same route. Disconnected nodes return `no-path`, missing
   endpoints return `unknown-entity` — never an empty list that reads as success.
3. **Filters narrow before layout.** `filterGraph` runs ahead of placement so a
   hidden node cannot stretch the canvas band or leave a dangling edge.
   `verifiedOnly` and `minConfidence` keep an entity only while it has a
   qualifying claim; edges come from `entity.links` (relation types), so the
   relation facet is what narrows edges. Documented in the module because the
   data model has no claim→edge link.
4. **Saved views are store data.** A view is `{ name, filter, layout, focusMode,
   viewport }` validated by Zod (`graph-views.ts`), stored in
   `StudioState.graphViews` and therefore inside the existing persistence
   envelope (IndexedDB-backed, validated on every load, cap 50). No second
   localStorage corpus.
5. **Backup includes views.** `data/canvas.json` now carries `graphViews`; the
   archive validator parses it with `SavedGraphViewsSchema` and restore composes
   it like the other canvas fields (`replace` replaces, `merge` merges by id).
   Archives written before this field existed restore with an empty list.
6. **Results are list-first.** The query panel renders the path as an ordered
   list plus an `aria-live` summary, and the canvas highlight is additive: an
   entity on the path gets a saffron ring, an edge on the path the saffron
   stroke. Keyboard users can select both endpoints from native `<select>`
   controls and read the result without looking at the SVG.

## Delivered

- `src/lib/studio/graph-query.ts` — `filterGraph`, `findShortestPath`,
  `pathNodeNames`, `pathEdgeKeys`, `undirectedEdgeKey`, facet counters.
- `src/lib/studio/graph-views.ts` — schemas, `buildSavedGraphView`,
  `upsertSavedGraphView` (replace-by-id, newest first, capped),
  `removeSavedGraphView`.
- `src/lib/studio/slices/graph-views-slice.ts` + store/types/hydration/schema
  wiring (`graphViews` is a persisted key, defaulted for older envelopes).
- Backup: `archive-format.ts` `BackupCanvas.graphViews`, archive build/verify,
  `restore.ts` composition, `BackupPanel` pass-through, `ImportOptions`.
- UI: `graph-query-panel.tsx` (filters, path, saved views) wired through
  `graph-toolbar.tsx` and `graph-view.tsx`; `GraphEdgeElement.pathHighlighted`;
  graph i18n strings.
- AI: `find_path` tool in `src/lib/ai/tools.ts` with hop relations and names.
- MCP: `LibraryIndex.shortestPath` and the `find_path` tool in `packages/dks-mcp`
  (closes the ADR 050 deferral).

## Verification

- `src/lib/studio/graph-query.test.ts` — direct, multi-hop, cycle, disconnected,
  unknown endpoint, self-path, dangling link, plus every filter facet.
- `src/lib/studio/graph-views.test.ts` — schema round-trip, zoom rejection,
  name cap, replace-by-id, list cap, delete.
- `src/lib/ai/tools.test.ts` — `find_path` found/no-path payloads.
- `packages/dks-mcp/src/library-index.test.ts` — path chain, disconnected,
  self, cycle.

## Deferred

- URL hash state for the active view name (item 5 of the issue). It needs
  ADR 037 hash rules applied to the router before a name can be encoded
  safely; the acceptance criteria do not depend on it.
- Visual query builder; the panel is the structured form of the same queries.
