# Plan 208 — Typecheck the Playwright suite

**Status**: Complete
**Date**: 2026-11-13
**Trigger**: A type error in a new e2e spec passed the pre-commit gate, CI, and
review. It surfaced only because the author ran `tsc -p tsconfig.json` by hand.

## Problem

Nothing in this repository typechecks `e2e/`.

| Project | `include` | Covers `e2e/` |
| --- | --- | --- |
| `tsconfig.app.json` | `src`, generated `next-env.d.ts`, `.next/types/**` | No |
| `tsconfig.test.json` | `src/**/*.test.*`, `tests/` | No |
| `tsconfig.json` | `**/*.ts` | Yes — but no script, hook, or CI job runs it |

Playwright transpiles specs with esbuild, which strips types without checking
them. A spec that passes an `unknown[]` where the store expects its envelope
type therefore runs fine, passes, and ships — the error only appears the day
the fixture changes shape and the failure mode becomes a runtime one inside a
browser, which is the most expensive place to debug it.

Evidence, from PR #1113: `buildSeededEntities()` was annotated `unknown[]`;
`seedStore()` takes `PersistedStudioState`. `pnpm typecheck` passed,
`pnpm typecheck:test` passed, `pnpm lint` passed, `quality_gate.sh` passed,
CI passed. `tsc --noEmit -p tsconfig.json` reported `TS2322` immediately.

## Decision

Add a third project, `tsconfig.e2e.json`, extending `tsconfig.base.json` with
`e2e/**/*.ts` and `playwright.config.ts`, and a `typecheck:e2e` script. Wire it
into every gate that already runs the other two:

- `scripts/minimal_quality_gate.sh` (pre-commit hook)
- `scripts/lib/language-checks.sh` (pnpm and npm branches)
- `.github/workflows/ci-and-labels.yml` (the job that owns the test program)
- `do-harness.toml` / `agents-docs/HARNESS.md` `feedback` sensor

Why the root `tsconfig.json` is not simply the gate: it also pulls in
`.next/types/**`, which only exists after `next typegen`, so a standalone
`tsc -p tsconfig.json` is not reproducible on a fresh checkout without build
output. A narrow project is deterministic and fast (2.6 s for 46 spec files).

Why not fold `e2e/` into `tsconfig.test.json`: that project sets
`types: ["node", "vitest/globals"]`. Playwright specs must not see `vitest`
globals — a spec calling `describe()` without importing it would typecheck and
then fail at runtime.

## Verification

The check was made to fail before being trusted (LESSON-041): appending
`const typecheckProbe: number = "not a number"` to
`e2e/graph-frame-timeline.spec.ts` produced

```text
e2e/graph-frame-timeline.spec.ts(268,7): error TS2322: Type 'string' is not assignable to type 'number'.
```

and restore returned the project to exit 0. The full 46-spec suite was clean on
introduction, so no pre-existing errors are being suppressed.

## Cost

2.6 s on the pre-commit gate, plus the same in CI, for 46 spec files — the
whole `e2e/` surface, which is where the least-reviewed code in the repository
lives.
