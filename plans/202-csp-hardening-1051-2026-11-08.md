# Plan 202 — CSP hardening (#1051)

## Goal

Replace the blanket `connect-src https: wss:` with an explicit allowlist so an
injected script cannot exfiltrate the corpus, add restrictive response headers,
and gate regressions with a CSP-violation E2E plus unit pins.

## What changed

- New single source of truth `src/lib/security/csp.ts` (`CONNECT_SRC_SOURCES`,
  `IMG_SRC_SOURCES`, `PERMISSIONS_POLICY_VALUE`, `CROSS_ORIGIN_OPENER_POLICY_VALUE`).
- `next.config.ts` builds `connect-src` / `img-src` from that module and sends
  `Permissions-Policy` + `Cross-Origin-Opener-Policy: same-origin-allow-popups`.
  `CORP`/`COEP` omitted: cross-origin model assets must stay loadable.
- `connect-src` allowlist: `self`, `https://openrouter.ai`, Hugging Face model
  hosts + `cdn.jsdelivr.net`, `wss://y-webrtc-eu.fly.dev`, loopback `ws:`/`http:`
  and `http://*.local:*` (validator-checked Ollama LAN case).
- `img-src` narrowed to `self` + model hosts + `data:`/`blob:`.
- Residual: `script-src` keeps `'unsafe-eval'` (measured `onnxruntime-web` need)
  and `'unsafe-inline'` (no Next nonce pipeline without breaking precache).
- `e2e/csp-violations.spec.ts` drives every primary view and fails on any
  `securitypolicyviolation` / CSP console error.
- `src/lib/security/csp.test.ts` pins no blanket `https:`/`wss:` and presence of
  AI/model/signaling/loopback hosts.
- ADR 045 extended with the XSS/exfiltration discussion.
