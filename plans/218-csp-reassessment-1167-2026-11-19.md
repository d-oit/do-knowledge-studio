## Nonce evaluation (the #1167 "evaluate" question, answered)

Next.js `headers()`/middleware nonces were evaluated and **not** adopted:

1. The app is a statically prerendered export with a service-worker precache
   contract (ADR 041); per-request nonces change HTML per response, which
   conflicts with precached offline pages (the offline shell must load
   without a server to mint a nonce).
2. Vercel Hobby serves the single production deployment; middleware-injected
   headers cannot reach SW-served responses offline, so the nonce pipeline
   would need a hash-based build-time alternative for the offline shell —
   tracked with the nonce work itself in **#1051**.

Hash/SRI authorization of inline scripts is feasible at build time in
principle but shares the same precache coupling; revisit when #1051 lands or
when the model runtime drops `eval` (then `unsafe-eval` goes with it — the
measured, not assumed, trigger).
