# Plan 195 — Markdown / folder / Obsidian-vault import (#1054)

## Goal
Let new users arrive with existing notes: accept `.md` files (single, multi,
folder) and `.zip` vaults in the Export view's import dropzone, parse them into
entities + claims + mention links, and stage them through the existing preview
+ recovery-snapshot flow.

## Non-goals
- No export changes (`buildMarkdownExport` untouched); round-trip is achieved
  by a dedicated parser for the export shape, not by changing the export.
- No Entity schema migration: Obsidian `aliases` map into `tags` (same trick
  as #1055's wikilink resolution); unknown frontmatter keys are reported as
  warnings and ignored (there is no metadata field on `Entity`).

## Design

### New pure modules (`src/lib/import/`, no framework imports)
- `markdown-import.ts` — vault parser + shared two-pass linker:
  - **Pass 1 — per file:** split YAML frontmatter (`title`→name,
    `tags`+`aliases`→tags, `type`→entity type w/ `concept` fallback,
    `created`→createdAt w/ ISO validation, `description`→description);
    entity id = path minus `.md` (same contract as OKF `parseOkfBundle`).
    Body keeps raw Markdown (render pipeline `ReactMarkdown`+`remarkGfm`
    without `rehype-raw` never executes HTML — documented, not re-solved).
    `#tags` extracted skipping code spans + headings via
    `getMentionCodeRanges`; claims via `extractClaimsFromText`.
  - **Pass 2 — link:** index entities by lowercase name, tag, and id;
    convert `[[Name]]`/`[[Name|display]]` (reuse `findWikilinkTokens`) and
    relative `.md` links (`[t](./x.md)`, `[t](../d/y.md)`, path-like
    `[[folder/Note]]` via basename fallback) into canonical
    `[@..](dks://entity/..)` tokens with `buildMentionToken`.
    Unresolvable names → **stub entities** (type `concept`, empty content,
    `crypto.randomUUID()` ids) listed in the preview.
  - **Conflicts:** same name on different ids (within the batch) → warning
    list, import still proceeds (names are not keys; ids are derived from
    distinct paths).
- `markdown-export-parse.ts` — exact reverse of `buildMarkdownExport` for the
  round-trip criterion: detects the `# DO Knowledge Studio — export` header,
  splits `---`/`# Name` sections, restores type/tags/description/content
  (wikilinks re-resolved by name), links, and `## Claims` lines
  (`- [verification] statement (confidence: N%[, source: S]) [— _evidence_]`).
- Limits (named constants, fail closed **before** any entity is built):
  `MAX_MARKDOWN_FILES = 500`, `MAX_MARKDOWN_FILE_BYTES = 1_048_576` (1 MiB),
  `MAX_MARKDOWN_TOTAL_BYTES = 20_971_520` (20 MiB),
  `MAX_VAULT_ZIP_BYTES = 10_485_760` (10 MiB compressed),
  `MAX_VAULT_UNCOMPRESSED_BYTES = 52_428_800` (50 MiB decompressed).
  Oversized input → `LimitError` message, no partial state, toast only.
- Result type: `{ entities, claims, stubNames, conflicts, warnings }`
  (warnings = per-file skips + ignored frontmatter keys; never throws on
  malformed files — collect and continue, OKF §11 style).

### Wiring (existing seams only)
- `use-export-handlers.ts`: `handleFileChange` routes `.md`/`.markdown`
  (single file → content sniff: export header? `parseMarkdownExport` :
  single-file vault), multi-select `.md` files (one vault batch), `.zip`
  (OKF fast-path first via `index.md`+`okf_version`, else vault-zip through
  `sanitizeZipPath` + size guards). Single `FileReader` per file ok.
- Dropzone: `accept=".md,.markdown,.json,application/json,.zip"`,
  `multiple`, folder support via a second hidden input with `webkitdirectory`
  (set through a callback ref — React types lack it); i18n hint text updated
  in the `import` scope (new keys only, N5 rule).
- `ImportPreview` gains optional `stubNames?: string[]` and
  `conflicts?: string[]`; dialog renders the two extra rows only when
  non-empty (existing JSON/OKF previews unaffected).
- Commit path unchanged: `importWithRollback(entities, claims)` → snapshot +
  rollback reused verbatim (recovery E2E already pins this).

### Tests
- `markdown-import.test.ts` + `markdown-export-parse.test.ts`: frontmatter
  mapping, aliases→tags, wikilink + relative-link resolution, stubs, conflicts,
  `#tags`/claims extraction, every limit failing closed, malformed files
  collected as warnings.
- Fixture vault `src/lib/import/fixtures/vault/` (nested folders, aliases,
  unicode filenames, broken links, duplicate names) read via `node:fs` in the
  vault test.
- Round-trip test: seed entities → `buildMarkdownExport` →
  `parseMarkdownExport` → names/tags/content/claims/link-targets equivalent.
- E2E `e2e/markdown-import.spec.ts`: `setInputFiles` a vault zip → preview
  shows counts + stubs + conflicts → confirm → entities present → restore from
  the pre-import recovery snapshot (mirrors `recovery-restore.spec.ts`).

## Acceptance mapping (#1054 criteria)
1. Obsidian zip → entities/tags/resolved links; preview lists stubs+conflicts.
2. Export→re-import equivalent library (round-trip test).
3. Zip bomb/oversize fails closed, no partial state (limit tests).
4. No network calls (pure parsing; `fflate`/`yaml` local; E2E offline-safe).
5. E2E: drop → preview → confirm → snapshot restore.

## Risks
- `webkitdirectory` typing (mitigated: callback ref + `setAttribute`).
- Folder input in Playwright (mitigated: multi-file `setInputFiles` covers
  the same batch path; `webkitdirectory` is a picker convenience).
- 500 LOC/file (mitigated: two modules + tests split).
