# Plan 201 — Synthesis Inbox: AI extraction with a review gate (#1057, 2026-11-08)

**Status**: Implemented on `feat/1057-synthesis-inbox`.
**Goal**: turn a note into reviewed knowledge without letting a model write to the
corpus. Issue #1057, ADR 054.

## Shape

```text
note ──▶ buildExtractionMessages ──▶ provider (sendChat)
     ◀── parseExtractionResponse (size cap ▸ JSON ▸ Zod ▸ bounds ▸ evidence check)
     ──▶ toProposals (duplicate flag, provenance) ──▶ proposals slice (pending)
                                                     │
                                        Accept ──────┴────── Reject
                                          │                    │
                              commitEntity / addClaim       status=rejected
                              (source = ai:<model>, unverified, one Undo step)
```

## Acceptance criteria → evidence

| Criterion | Where it is enforced | Test |
| --- | --- | --- |
| No AI output touches entities/claims until accepted | Accept is the only writer; the slice test asserts the corpus is untouched after `addProposals`. | `proposals-slice.test.ts` |
| Provenance stored on accepted claims | `source = ai:<model>`, `verification = unverified`, `evidence` = quoted span, `entityId` = source note; `buildClaim` stamps the timestamp. | `proposals-slice.test.ts` |
| Malformed/oversized output rejected, no partial writes | `parseExtractionResponse` returns a reason and the caller writes nothing: `too-large`, `not-json`, `schema`, `too-many`, `empty`. | `extraction.test.ts` |
| Works with Ollama and the local adapter; privacy disclosure for remote | `leavesDevice` is true only for `openrouter`; the panel renders the matching note; settings come from `loadAISettings`, so both local providers are first class. | `extraction.test.ts` (privacy), manual check |
| Undo restores the pre-accept state | `acceptProposal` calls `commitEntity`/`addClaim`, each of which pushes one snapshot. | `proposals-slice.test.ts` |

## Deliberate omissions

- **No embedding-based dedupe.** The issue suggests vector similarity; extraction
  must work offline and with the local provider, and a duplicate flag that needs a
  network call would rarely be shown. Token-overlap similarity (`0.8`) plus exact
  normalized-name matching is deterministic and testable. Embedding similarity is
  a follow-up once a local vector index is guaranteed to be warm.
- **No model-output "repair" loop.** One retry with a repair prompt doubles cost
  and can still fail; the panel reports the reason and the person retries.
- **Proposals are not exported in `.dksb`/JSON backups.** They are review state,
  not knowledge; an accepted item is already in the exported corpus.
- **Model quality evaluation is a recorded fixture, not a live call.** CI has no
  provider; the fixture encodes expected precision bounds for a recorded answer.
